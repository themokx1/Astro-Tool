Your source files stay unchanged

AstroTool creates verified copies inside the new library. It does not overwrite existing files and never deletes files as a standalone action.

The simple shape of a library

Library → Project → Night → Capture → Frames. A project collects one sky target over time; a night records one observing date; a capture groups images made with the same setup. Frames can be light, flat, dark, or bias.

You only answer questions that genuinely need your judgement: where the library should live, what target you photographed, the observing date, and a useful capture name. The app does not guess when it is unsure.

The safety rule, precisely

In the source folder, AstroTool does not move, rename, or delete anything. In the destination library, it may create new folders and new file copies. It never overwrites an existing destination file. If verification fails, it only cleans up the incomplete temporary copy it just created.

V5 prototype: an offline iPhone companion

AstroTool V5 adds a companion app for your own iPhone. You build and install it yourself from Xcode; the Mac and the phone then sync primarily over the local network, direct device to device, with an encrypted .astromobile package — if that is not available, AirDrop remains the full fallback. Neither path uses an internet account or cloud sync.

  1. What you needA Mac running AstroTool, an iPhone on iOS 26, a free Apple Account, and Xcode from the Mac App Store.
  2. One-time installSign in to Xcode with your Apple Account, select yourself as the Personal Team, connect the iPhone, and build the AstroTool companion onto it. If iOS asks, trust the developer app in Settings.
  3. The seven-day limitA free Apple Account's provisioning expires after seven days. The app stays installed, but you must build and run it from Xcode again — that is, reinstall it — before it will open. Your checklist ticks and notes on the phone are not lost.

Daily use. On the Mac, open Settings → iPhone Sync and click “Sync with iPhone directly.” The Mac starts advertising itself on the local network. On the phone, open the AstroTool companion and tap “Connect to my Mac.” The first time, both devices show the same six-digit pairing code — compare it and confirm on both; this only happens once per pair of devices. Making this connection asks for a one-time local network permission, used only so your own two devices can find each other and exchange the briefing — nothing else can see it. The Mac then builds and sends the sealed .astromobile package over the local network. If you decline the permission, or the network is unavailable, the phone offers the same one-time QR code and AirDrop exchange as a full-value fallback.

In the field. The briefing, targets, and capture plan stay readable in Airplane Mode. Tick checklist items and write notes offline; they live only on the phone until you send them back.

Returning changes. On the phone, send the return package back over the same paired local-network connection, or AirDrop it to the Mac if the direct connection is not available. The Mac shows exactly what changed and applies nothing until you approve it; conflicting notes default to keeping both. The phone's queue only clears once a later Mac package confirms which items were applied.

What travels, and what never does

Original photos are not transferred. iPhone cannot modify files in the image library — the Mac stays the sole owner. Checklist and notes only come back from the phone; it never initiates a delete, move, or rename. There is no CloudKit, no iCloud sync, and no background refresh — this is a local prototype for your own device, and both apps must stay in the foreground to sync, whether over the local network or AirDrop.

Developer details and troubleshooting

The project is generated from the repository root with xcodegen generate using project.yml; run the iPhone app onto your device with Xcode's AstroToolMobile scheme.

If the seven-day provisioning has expired, reconnect the iPhone and run the same scheme from Xcode again — this does not erase the checklist and note data already on the phone.

Scanning the QR code requires a one-time camera permission, used only to read the one-time package key.

If you declined the local network permission by mistake, or the Mac and phone are not on the same network, you can grant it again at any time in Settings → Privacy & Security → Local Network for the AstroTool companion; the AirDrop exchange works exactly the same in the meantime.

If a package turns out to be corrupted or tampered with, the app refuses it outright rather than opening it partially — request a fresh package from the Mac.
