CLI reference

Every subcommand, grouped, with a one-line description and one runnable example each.

Guide · Features · Install · Download

Every command accepts --root PATH to override the library location, and most support --json for machine-readable (snake_case, sorted) output. Every --json output gets a schema_version field at the root; for commands where the root used to be a plain array, the response is now wrapped as {"schema_version": "1", "items": [...]}; exact changes are listed in the release notes.

Exit codes

CodeMeaning
0Success.
1General/usage error (missing or invalid flag, unknown subcommand).
2TCC/volume error: the library isn't reachable (missing Full Disk Access, or the volume isn't mounted).
3Target/session not found: --target/--date doesn't identify anything in the index (e.g. stats, solve, match, link-calib, report, target-report).
4External tool error: Siril isn't found at the configured path (e.g. solve).
5verify found at least one confirmed content mismatch (content-changed: same size/mtime but a different hash, suspected silent corruption). modified and suspicious modified-in-place don't count toward this; a read error returns exit code 1, not 5.

Basics

scan
Walks the library and refreshes the internal SQLite index: always the first step. Its --json output also carries a changed_targets field: the targets where this run found an added/updated/missing file, useful for deciding which targets to run rate/audit on next in a pipeline. --refresh-meta re-reads metadata for already-known files too, not just new ones.
astrotool scan --root ~/Astro
audit
Error list sorted into three severities, plus duplicate detection; with --suggest it writes a reviewable suggestion script. --out PATH (only together with --suggest) can write the script outside the library instead of the fixed .astro_tool/suggestions/ spot; --out - prints the script text to stdout without writing a file. Its --json output also carries a diff field when a previous audit run exists: new/resolved/unchanged group counts plus the new groups' keys (severity/category/group_key). If the two runs' duplicate-detection setting differs, or is unknown for the older run, the duplicate category is dropped from both sides and omitted_categories flags it. The diff is skipped on the first run. --no-duplicates turns off duplicate detection entirely for a run, if you only care about structural errors or suspicious findings.
astrotool audit --suggest --include-suspicious --out ~/Desktop/fix.sh
cleanup
A capped summary of already-identified residue/duplicate findings, plus suggestion-script generation. --out PATH|- works the same as with audit --suggest. Its --json output also carries a storage field: per-target size broken down by area (sessions/stacks/processed/other), sorted by size descending; the same data the app's Cleanable segment shows in its "Storage" block, which is why it lives on the existing cleanup command rather than as a separate subcommand.
astrotool cleanup --suggest --limit 50 --out -
verify
Fixity/bitrot check: re-reads every indexed, non-missing file that already has a baseline SHA-256 and compares it against the stored checksum. The normal check only reads; it just flags mismatches, restoring from a backup stays a human decision. --target T/--path P narrows the scope; --sample N (1-100) checks a random sample. The explicit --baseline only fills in missing hashes in AstroTool's database, never touches the image files, and can't be combined with --sample. Per-file outcome: ok; content-changed (same size/mtime, different hash, sure_error); modified (both size and mtime changed, intentional); modified-in-place (only mtime changed, suspicious); or a suspicious read error. The JSON gives summary, coverage, and items blocks.
astrotool verify --baseline --json
astrotool verify --sample 20 --json
ack
CLI version of the Audit page's "I know about this, it's fine" marks: accepting error groups (add), reverting them (remove), listing them (list). The <category|groupKey> is exactly the ack-key shape from audit --json's findings.
astrotool ack add "residue|*.seq" --note "known, intentional"
stats
Per-target integration/frame summary; --target for a session breakdown, --tag to filter, --filters for a per-filter integration breakdown (mono LRGB/SHO "how many hours do I have per filter"); for a whole target (not narrowed by --date) the per-filter goal:F=<hours>h target/missing also shows up, if set.
astrotool stats --target M31 --filters
nights
A cross-target night browser: every session in one table, newest date first, with frame/integration and quality columns (FWHM, duty cycle): the cross-target counterpart of stats --sessions narrowed to one target.
astrotool nights --year 2026 --month 3
trends
A long-term, session-level time series across targets: median FWHM (arcseconds, or pixels with is_pixel_fallback=true when there's no pixel scale), background e⁻/s/″², or efficiency% (duty cycle): chosen with --metric, as date+value pairs, oldest first. --setup narrows to one specific EquipmentProfile setup-fingerprint description; --from/--to filter on the session's canonical start date.
astrotool trends --metric fwhm --from 2026-01-01 --json
new-session
Creates a new session directory (YYYY-MM-DD) with a README template for a target.
astrotool new-session --catalog M --name 31 --date 2026-03-15
capture list | create | assign
Manages standalone capture groups within one target/date session. A capture separately records the sensor mode (osc/mono), its character (broadband/narrowband/dual_band), and the exact filter maker, model, and name (--filter-maker/--filter-model/--filter-name), plus an optional --notes note. assign attaches exactly one already-indexed file to the chosen capture, only accepts a path within the given target/date session, and can override the file's filter data with the same --filter-* flags.
astrotool capture create --target IC_1396 --date 2026-08-08 \
  --name "OSC · dual-band filter · 300s" --slug osc-duo-300s --sensor osc \
  --signal dual_band --filter-maker <MAKER> --filter-model <MODEL>

astrotool capture assign --target IC_1396 --date 2026-08-08 \
  --group osc-duo-300s --path sessions/IC_1396/2026-08-08/light_0001.fit
session-convert plan | apply | rollback
A transparent converter scoped to exactly one chosen target/date session. By default, plan only plans a logical classification: it lists the capture groups it recognizes, raw frames, calibration frames, artifacts, uncertain decisions, and conflicts, but moves nothing. The separate --physical flag produces an itemized source-to-destination move plan. apply only runs with a saved plan and --yes confirmation; it refuses to overwrite, checks the session hasn't changed via a fingerprint, saves a receipt, and can be rolled back by that receipt's id.
astrotool session-convert plan --target IC_1396 --date 2026-08-08 \
  --out ~/Desktop/ic1396-plan.json

# Only after reviewing the full preview:
astrotool session-convert apply --plan ~/Desktop/ic1396-plan.json --yes
astrotool session-convert rollback --id <conversion-id> --yes
config
The currently effective configuration (show) or the path to config.json (path). config show gives human-readable, per-section key-value output by default; --json for the full structure.
astrotool config show --json
tag
Adds, removes, and lists free-text target- or session-level tags.
astrotool tag add --target M31 goal:8h
goal
Sets or clears a target's goal hour count (a goal:<hours>h tag): the same format the app's goal editor writes, so the two are freely interchangeable. --filter F sets a per-filter goal (goal:F=<hours>h, R11), independent of the overall goal; the two can coexist freely. goal list --target T returns the per-filter have/goal/missing breakdown.
astrotool goal set --target M31 --filter Ha --hours 12
astrotool goal list --target M31 --json
note
Shows (show, merged with the README) or writes (set) session night notes (Bortle/SQM/seeing/free text). Never touches README.txt; an empty --value clears the key.
astrotool note set --target M31 --date 2026-03-15 --key Bortle --value 5

Quality

rate
Scores light frames with native metrics, optionally hybridized with the Siril CLI; flags outlier frames.
astrotool rate --target M31 --date 2026-03-15
quality
A measured quality summary for one target/session (FWHM, background, rank, outliers).
astrotool quality --target M31 --date 2026-03-15
sensor
Lists measured sensor profiles (bias level, read noise, dark rate, EGAIN), or re-measures with --measure from bias/dark frames: every measurement also joins the measurement history, while the sensor_profile table only shows the latest. --history gives the full measurement history grouped per combo (date, read noise, dark rate, estimator version); can't combine with --measure.
astrotool sensor --measure
astrotool sensor --history --json
ingest-dss
Reads DeepSkyStacker .info.txt star metrics and .dssfilelist accept/reject decisions; doesn't run automatically with scan.
astrotool ingest-dss
expose
Ideal sub-length and relative SNR advice, computed from measured sensor noise and per-Bayer sky background. Without --target, a one-line table per target.
astrotool expose --target NGC7000

Calibration

calib
A calibration coverage gap list (which exposure/temperature combination still needs a dark, which filter still needs a flat); --health for the flat-discipline report, --flats for just the per-filter flat coverage. --shopping [--date YYYY-MM-DD] [--site NAME] gives only the gaps needed for that night's actually-visible targets; in JSON you get night, site, and items fields. The three modes can't be combined.
astrotool calib --shopping --date 2026-03-15 --site "Summer house" --json
match
Matches a given target+date session's light/flat/dark/bias set and lists the problems it finds.
astrotool match --target M31 --date 2026-03-15
link-calib
Hardlinks the matching master calibration frames next to the session; --dry-run for a preview, without --yes it only flags what it would do.
astrotool link-calib --target M31 --date 2026-03-15 --dry-run
health
Night hardware health: cooler stability and focus trend for one session.
astrotool health --target M31 --date 2026-03-15

Planning

plan
Tonight's target ranking (culmination, max altitude, visibility window, moon interference, moon-aware filter suggestion); --month for the 30-night planning calendar. --out PATH|- exports the daily plan as CSV, with machine-readable night, raw filter, filter_missing_hours, and missing_hours columns alongside the existing fields. --out - writes to stdout and can't be used together with --month. --site <name> picks a location from config.json's sites list (instead of the configured default): an unknown name errors out listing the configured names; if no sites are configured, the old site/FITS-median automation still applies unchanged.
astrotool plan --site "Summer house" --out plan.csv
night-info
Just tonight's dark-hours/moon summary (works without a target coordinate too): dark hour count, moon illumination, and rise/set time, using the same site resolution as plan. The same --site <name> is available here too.
astrotool night-info --date 2026-03-15 --site "Summer house"
projects
Per-target pipeline status: where capture/calibration/stacking/processing stands.
astrotool projects
panels
WCS-based integration tracking for a mosaic target's panels (how much time each panel got).
astrotool panels --target M_Milky_Way
solve
Plate-solves targets without coordinates (e.g. wide-field CR3) using Siril, with a per-session frame-count cap.
astrotool solve --target M_Milky_Way --frames 2

Export

export
AstroBin bulk-import CSV, a richer session CSV, or a human Markdown log for one target. In AstroBin format, a separate row is produced for every (session, filter, nominal exposure) group, so Ha/OIII/SII frames shot the same night at the same exposure don't blur together. Each row gets its own numeric ID from config astrobin.filterIds, resolved space- and case-insensitively; an unmapped filter keeps its name, and the stderr warning lists every missing name.
astrotool export --target M31 --format astrobin
stacklist
Selects and exports a session's best frames (hardlink + .dssfilelist + Siril .ssf + manifest.csv) for a DSS/Siril/WBPP workflow. --capture SLUG narrows both the quality selection and the export to a single capture group, so for example a short OSC test run and a multi-hour dual-band sequence can be stacked separately. For multi-filter material, a separate lights/<FILTER>/ subfolder and a separate .dssfilelist/.ssf pair per filter (PixInsight WBPP-friendly; an empty or colliding slug between two filters gets a filter_1/_2-style suffix to protect against collisions); manifest.csv is always one file at the root, whose first line is a # library_root: <absolute path> comment, followed by columns: file, filter, score, fwhm_px, session_date, verdict, linked_name (the name actually used for the link: on a filename collision within a bucket this differs from the source filename, e.g. part2__img_0001.fit). --keep is the shared keep ratio; --keep-filter "Ha=0.9,OIII=0.7" overrides it per filter (comma-separated list, each in (0, 1], filter name case-insensitive; the none key applies to the group of frames with no filter; an unknown filter name gets a stderr warning, not an error). Re-exporting syncs an existing export with the fresh selection: hardlinks no longer in the selection disappear from the lights/ tree, strictly only there (the library's original files are untouched), and the output reports it ("N stale links removed"). By default it exports under .astro_tool/stacklists/<target>-<date>/; --out PATH exports directly into PATH instead (PATH becomes the stacklist directory itself, and can be outside the library; a copy is made instead of a hardlink across volumes, and the output reports that too). --out - isn't supported, since this exports a whole directory tree, not a single file: it stops with a clear error.
astrotool stacklist --target IC_1396 --date 2026-08-08 --capture osc-duo-300s \
  --keep 0.8 --out ~/Desktop/IC1396-osc-stack
stacks
Discovered finished stack files for a target, grouped into variant families (original/edited/starless/starmask/export); --verbose lists the variants too.
astrotool stacks --target M31 --grouped
report
A standalone HTML night report: timeline, quality, altitude & moon, calibration, to-dos, and a filter breakdown computed only for that session's date. Writes to the report directory by default; --out PATH for exactly the given file, --out - to send the HTML to stdout.
astrotool report --target M31 --date 2026-03-15 --out ~/Desktop/M31-2026-03-15.html
target-report
A standalone HTML target report: every session, stack, calibration coverage, and quality figure for one target, on one page, with a project-level per-filter have/goal/missing table. Writes to the report directory by default; --out PATH for exactly the given file, --out - to send the HTML to stdout.
astrotool target-report --target M31 --out -

Other

search
Searches Bortle/SQM/seeing notes written into a session's README.txt (and the note editor) by key or value; with --all, a full sidebar-style search instead: targets, sessions, files, and notes at once.
astrotool search M31 --all
